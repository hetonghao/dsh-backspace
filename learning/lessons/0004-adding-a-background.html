Backspace 课程 · 第 4 课

新增一种背景

壁纸、视频、渐变——这些都能加，而且不需要动三条安装路径。 但要绕开一个坑：现有存储层放不下素材。 本课给出可落地的分层设计，以及每一步的验证方式。

1目标结构：背景变成"可插拔策略"

现在 skin.html 硬编码加载 ocean.js。 改造目标是让它变成一个分派器：按 type 选一个渲染器模块。 这样以后加背景就是"加一个文件"，不用改控制器。

2最小实现：静态壁纸

先做最简单的，验证整条链路通。新建 shared/background-image.js：

// 静态壁纸背景。遵守与 ocean.js 相同的三条约定。
const query = new URLSearchParams(location.search)
const src = query.get('src')          // blob: 或 data: 或 https:

if (!src) {
  // 没素材就什么也不画，让下面的控制器退回海洋
  window.parent.postMessage({ type: 'bs-bg-error', reason: 'missing-src' }, location.origin)
} else {
  const image = new Image()
  image.src = src
  image.decoding = 'async'
  image.style.cssText = 'position:fixed;inset:0;width:100%;height:100%;' +
    'object-fit:cover;pointer-events:none'

  const reveal = () => document.body.classList.add('ready')   // ① 淡入契约
  image.decode().then(reveal, reveal)                          // 解码失败也要显示，避免白屏
  document.body.append(image)
}

// ② 只接受 parent 且校验 origin
window.addEventListener('message', (event) => {
  if (event.source !== window.parent) return
  if (event.origin !== location.origin) return
  const data = event.data
  if (data?.type === 'bs-bg-set' && typeof data.src === 'string') {
    document.querySelector('img')?.setAttribute('src', data.src)
  }
})

然后在 skin.html 里改成分派（现在它硬编码 ocean.js?skin=1）：

const query = new URLSearchParams(location.search)
const type = query.get('type') ?? 'ocean'

const MODULES = {
  ocean: './ocean.js?skin=1',
  image: './background-image.js',
  video: './background-video.js',
}

import(MODULES[type] ?? MODULES.ocean)
  .catch(() => import(MODULES.ocean))   // 任何失败都退回海洋，绝不白屏
为什么退回海洋很重要 素材可能损坏、格式不支持、URL 失效。背景是装饰层，它失败绝不能让 Harness 不可用。 现有代码在 WebGPU 不可用时也只是在 console 报错并保持页面可读——新背景要守住同一条底线。

3素材从哪来：两条路径

必须处理的一个细节 createObjectURL() 产生的 URL 会让 Blob 一直驻留内存， 直到 revokeObjectURL() 或页面卸载。 换素材时必须先撤销旧的，否则连续换十次壁纸就泄漏十份数据。

4要新增的存储能力

现有 storage 接口只有 get/set，且三条路径都只能存小标量。 加大素材需要扩展这个接口——这是本次改造唯一需要碰适配器的地方， 所以要想清楚边界。 

// 建议：把"大对象"和"设置"分开，不要混进同一个 get/set
const storage = {
  get: ...,        // 保持原样：小标量
  set: ...,        // 保持原样
}

// 新增，仅背景功能使用
const assetStore = {
  put: (key, blob) => Promise<void>,
  get: (key)        => Promise<Blob | undefined>,
  remove: (key)     => Promise<void>,
}

createController({ assetUrl, storage, assetStore })
路径assetStore 实现备注
扩展IndexedDB（扩展自身 origin）storage 权限已够
静态 / DSH 插件IndexedDB（Harness origin）与宿主共享配额
三处实现几乎相同 IndexedDB 的代码是通用的，可以抽成一个共享函数由三个适配器各自调用。 不要把 IndexedDB 逻辑写进 skin-core.js—— 控制器不该知道持久化细节。

5视频特有的三个坑

① 自动播放策略

带声音的视频会被浏览器拦截。muted + autoplay + playsInline 是必填组合；play() 返回 Promise，必须 catch， 否则在受限环境会抛未处理拒绝。

② 解码开销

4K 视频当背景会让 GPU 解码器和 WebGPU 抢资源。建议在控制器里限制 （比如超过 1080p 提示降级），或者让用户自己承担。这需要真机测帧率—— 我没有你的机器数据，别信任何"应该没问题"的说法。

③ 与「减少动效」冲突

现有渲染器在 prefers-reduced-motion 下会降到约 20 FPS 并显著减速。 视频背景应当尊重同一偏好：抽首帧当静态图，而不是继续播放。 

// 尊重 reduced-motion：不播放，只留首帧
const reduce = matchMedia('(prefers-reduced-motion: reduce)').matches
if (reduce) {
  video.removeAttribute('autoplay')
  video.currentTime = 0.1        // 确保有帧可显示
} else {
  await video.play().catch(() => { /* 被拦截：保持首帧 */ })
}
