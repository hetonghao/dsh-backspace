两行并列。想突出自己可以调行序或措辞，但第一行不能删。

MIT 到底要求什么

可以必须不存在的要求
改名、换标识 附带含版权行的许可全文 必须写致谢
闭源分发自己的新增部分 — 必须链接上游仓库
商业化 — 必须说明"基于某项目"
不再自称 fork — 必须通知原作者

#操作可逆优先级
1 打通 npm 发布
npm login → npm publish		 否 最高（当前文档指引安装一个不存在的包）
2 统一两套配置来源 是 高（消除字段漂移）

7 解除 GitHub fork 关系 否 低（需平台侧操作）
8 重写渲染器降低上游代码占比 否 低（工作量最大，且需先有其他成绩）
为什么 1 号最紧急 docs/dsh-plugin.md 和 README.md 都写着让用户执行 dsh plugin add dsh-backspace@1.2.5， 但实测 npm view dsh-backspace 返回 404—— 这个包从未发布。按文档操作的用户必然失败。

fork 关系的真相

概念是什么怎么改
upstream remote 本地 git 配置，指向上游仓库 git remote remove upstream，随时可加回
GitHub fork 标记
（"fork": true）		 GitHub 平台元数据，关联 fork 网络 删 remote 无效；需 GitHub Support 或迁移到新仓库
git 历史里的上游提交 你仓库的提交历史 删不掉（除非重写历史，代价极大且破坏可追溯性）

解读 在自有代码占约 10% 时，「不署名」在技术上做得到，但作品实质仍是上游代码。 更现实的路径是：保留合规署名，把精力放在让自有代码成为主体 （新背景系统、新配置架构、新 slot 集成都属于这类）。
