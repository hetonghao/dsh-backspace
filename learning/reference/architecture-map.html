三条通道

方向机制内容
控制器 → 渲染器（初始）iframe URL 查询参数skin=1 · sea · t · auto · parentOrigin · quality
控制器 → 渲染器（更新）postMessage{type:'bs-set', sea, t, auto}
控制器 ↔ 存储注入的 storage.get/set全部持久化字段
渲染器的安全边界 shared/ocean.js 只接受 ev.source === window.parent 且 origin 匹配的消息。加新通道时不要放宽这两条。

控制器只要求两个能力

这是全仓库最重要的接缝。createController(options) 只依赖：

createController({
  assetUrl: (path) => string   // 资源根路径，三条路径各自不同
  storage: {
    get: (defaults) => Promise<settings>
    set: (patch)    => Promise<void>
    listen?: (cb)   => dispose   // 仅扩展路径提供
  }
})
路径assetUrl存储listen
浏览器扩展 chrome.runtime.getURL(path) chrome.storage.sync
skin* 前缀		 有（跨窗口同步）
静态安装 /dsh-backspace/${path} localStorage
bs* 前缀		 无
DSH 插件 /dsh-backspace/${path} localStorage
bs* 前缀		 无
扩展法则 能在 skin-core.js 里做的事，就不要动适配器。 一旦你需要适配器提供新能力（比如大文件存储），三条路径要分别实现——成本立刻 ×3。

四层接缝：改哪里

层典型需求改动面是否动 Harness
① 内容替换 换配色、换文案、换波参数 1 个文件里的常量 否
② 换渲染内容 壁纸、视频、渐变、粒子 新入口页 ＋ 控制器传参 否
③ 新配置项 新滑块、新开关、新持久化 skin-core 多处 ＋ 3 个适配器 ＋ 测试 否
④ 新 slot / 改结构 要一个宿主没有的挂载点 改 Harness 源码 是（升级即失效）
