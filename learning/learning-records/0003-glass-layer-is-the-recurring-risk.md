# 这个模块会反复坏（而且是同一个原因）

第 6 课把 1.2.1 / 1.2.3 / 1.2.5 和本次浮层修复排在一起，
发现四次症状不同但机制相同：**插件假设了某个 token 的用途，Harness 拿它画了别的东西**。

学习者已经理解这一点，并拿到了判据：按 Harness 的**语义**决定透明度，
而不是按"我认识哪个元素"逐条打补丁。同时接受了 alpha 复合是不可绕过的硬约束。

## Evidence

第 6 课课后测验答对了「四次事故的共同点」与「哪些 token 该保持不透明」，
说明已经理解"语义分层 vs 逐元素修补"的区别，而不只是记住了结论。

## Implications

- 之后的扩展课可以直接引用"这个改动碰了哪个 token、该 token 被谁消费"作为设计审查问题，
  不必再从头解释为什么共享层危险。
- 如果学习者决定给背景加独立透明度，应先复习 alpha 复合那一节，并预计需要重新设计层数。
- `reference/glass-tokens.html` 里的消费方统计是**版本相关**的，升级 Harness 后要重跑，
  不要当常量引用。
